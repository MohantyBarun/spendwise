      How it works

      No servers to pay for. Everything heavy happens on the phone.

      1. 1

        Capture

        A broadcast receiver sees each incoming SMS. Only bank debit alerts get past the parser; OTPs, credits, reminders and messages from personal numbers are dropped on the device.

      2. 2

        Store

        Amount, merchant, last four digits and reference number go to Cloud Firestore under the user's own ID. The SMS text itself is never uploaded. Offline writes sync later.

      3. 3

        Remind

        WorkManager runs a 9 PM job: if any recent payment has no description, a notification opens the list filtered to just those. Categories you pick are remembered per merchant.

      4. 4

        Report

        Every Sunday a rules engine compares the week with the previous four and writes concrete tips: categories above their usual level, frequent food orders, small payments adding up, budget pace.

      Security

      • Firestore rules let a signed-in user read and write only their own records, with type and size checks on every field.
      • The SMS receiver accepts broadcasts from the system only.
      • Optional fingerprint or PIN lock, Android backups off, amounts hidden on the lock screen.
      • The demo edition asks for no SMS permission at all: payments come from sharing a single message into the app.

      Built with

      • Firebase Authentication and Cloud Firestore (Spark plan)
      • WorkManager, BiometricPrompt
